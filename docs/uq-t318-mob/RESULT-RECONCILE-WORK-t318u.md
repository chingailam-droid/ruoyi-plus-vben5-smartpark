## 4. 建议改写点

1. 文首状态改为待重对照，并插入来源节。改写稿见 `SOURCE-HEAD-UQ-REQ-MOB-002-t318u.md` 与 `SOURCE-HEAD-UQ-MOD-WORK-001-t318u.md`。
2. 验收表增加「原积累」列。67 条区间对齐只放在大纲互核，不写入「对照通过」。
3. 巡检表把 `PATROL-05` 放在互斥的一行，或在打卡行写明 05 的职责在异常行。避免读者把 04～06 与 05、07～09 加总成 10。
4. 工单池「支持离线状态标记」改写成两句：列表可以显示离线草稿或离线标记；接单、改派、接警、审批、通知发送、回单保持在线，并带 `expectedStatus`。旧档的离线模型待 yd / 原设计出现后再归纳。
5. 在线动作与可排队对象合成一张边界表，需求 §4.1、§4.8 与模块 §3 共用，避免只在一处出现。
6. 扫码行保持「只解析园擎受信码，解析成功不自动写」。对照时看旧移动端是否存在扫码即写入；若存在，来源节记差异，正文维持不自动写。
7. 领导只读卡保持易办不挂、非 IOC、不得伪造实时。旧领导看板若绑在员工端，记入差异，不把旧画面路径当作易办范围。
8. 报修闭环的状态名从易办 01 §10.3 / 易管 01 §7.3 归纳进 UQ 之后，两份 01 才能当行为正文。未对照前，需求 §6 只保留「服务端单一事实源」这条约束，不宣布状态机已经对齐旧档。
9. 增加「需求上游编号 → 模块权威域」映射。审批同时挂 site-portal 与 billing、告警挂 shield 与 iothub，域界待原模块文档核对，不在本环境合并或拆分域。
10. IDENT-01 的句子保持现在的方向：不阻塞易管登录；阻塞的是与易办对客工单的一致性验收。旧账号体系待对照后再决定要不要加差异注记。
